# WealthForge OS — v1.1.0 Release Notes

**Release date:** 2026-09-01
**Codename:** Personal Investment Master — Intelligence Layer

## Summary

v1.1 extends the frozen v1.0.0 financial engine with a full intelligence
layer: 31 new widgets across wealth, investment, goal/liability,
behavioral, and scenario intelligence, a WealthForge Daily Brief, and a
redesigned Command Center. It was built and delivered as eight staged
milestones (IM-01 through IM-08), each inspected, implemented, tested,
audited, documented, committed, and pushed before the next began — per
`docs/21_INTELLIGENCE_MASTER_PLAN.md`'s staged-delivery plan.

No screen was added and no existing screen was removed: the eleven
screens from v1.0.0 (Command Center, Budget, Portfolio, Goals,
Liabilities, Insurance, Analytics, Data Center, Settings, Market, AI
Analyst) are unchanged in count. The intelligence layer surfaces entirely
on a reorganized Command Center.

## Engineering principles preserved throughout

Every widget in this release was built under the same non-negotiable
rules as the v1.0.0 engine (root `CLAUDE.md`,
`docs/07_FINANCIAL_CALCULATIONS.md`, `docs/08_DATA_TRUST_MODEL.md`):

- **Snapshot ≠ activity.** No widget infers a buy/sell/SIP from an
  observed quantity change; the documented ingestion path never
  fabricates a transaction that was never confirmed.
- **No fabricated data.** Missing NAV, cost basis, P&L, transaction, or
  benchmark history is never guessed — every affected widget reports
  `insufficient-data` with a stated reason instead.
- **PLAN vs POSITION vs ACTIVITY stays distinct.** A scenario (Goal
  Trade-Off Simulator, every Scenario Engine widget) never mutates a real
  goal, liability, or budget record — proven for Goal Trade-Off by an
  explicit before/after diff test.
- **Growth assumptions are observed, not invented.** Every Scenario
  Engine widget derives its growth rate from `computeCagr` over the
  portfolio's or net worth's own recorded history since inception; where
  that history is insufficient, the widget reports so rather than
  substituting a guessed market return. The one external convention used
  (the 4%-rule / 25x-expense FI target) is explicitly disclosed as such,
  never presented as a project-specific rule.
- **Trust and provenance carry through.** Every `Insight<T>` retains its
  coverage, trust state, provenance, and calculation basis; a headline
  figure is only as trusted as the records that feed it.
- **No financial arithmetic in React.** Every number a widget displays is
  computed in `src/domain/` or `src/views/`; `.tsx` files only format and
  render already-computed `Insight<T>`/`ScenarioResult<T>` values.

## Zero-cost verification

No paid dependency, service, or API key is required anywhere in this
release:

- `package.json` `dependencies` are unchanged from v1.0.0:
  `@prisma/client`, `exceljs`, `next`, `react`, `react-dom`. No new
  runtime dependency was added across IM-01 through IM-08.
- No new environment variable is required; `.env.example` remains
  accurate as-is — the AI provider still defaults to local Ollama with no
  key required, and market data still comes from AMFI's and Yahoo
  Finance's free, unauthenticated endpoints.
- The entire intelligence layer runs against the same local SQLite
  database (`data/wealthforge.db`) as v1.0.0 — no cloud service is the
  source of truth for any new widget.

## Known limitations (carried forward, not regressions)

- Several Investment Intelligence widgets (Growth Decomposition,
  Contribution vs Return, Portfolio Performance's XIRR, Investment Plan
  Adherence) depend on confirmed `buy`/`sip`/`sell` activity records. A
  data set that only ever imported position snapshots (the documented
  ingestion path never fabricates a transaction from an observed quantity
  change) will see these report zero contribution or insufficient-data —
  this is expected, not a defect (`docs/18_FAILURE_MODES.md`).
- Emergency Fund Runway always reports insufficient-data until the budget
  data model gains an essential/discretionary expense split (D-017).

## Upgrade notes

There is no data migration required for this release: no schema change
was made in IM-01 through IM-08. Existing v1.0.0 databases work unchanged
with v1.1.0 — every new widget is a read-only composition over data the
v1.0.0 schema already stores.
