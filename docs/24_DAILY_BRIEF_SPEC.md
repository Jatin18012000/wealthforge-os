# 24 — WealthForge Daily Brief Spec (v1.1, IM-07)

## What it is

A richer, AI-narrated version of the M10/M11 rule-based report
(`src/views/reportView.ts`), built from the v1.1 intelligence layer's own
`Insight<T>` outputs (IM-02 through IM-05) instead of the Command Center +
Market sections the original report used. It answers the questions the
v1.1 directive named: what is my position, what changed, why, where has
reality deviated from plan, what risks exist, how are my goals doing, what
does my portfolio look like, and is my data trustworthy.

## Architecture — extends, does not replace, M10/M11

```
Insight<T> outputs (IM-01–IM-05)  →  Report (src/views/dailyBriefView.ts)
                                          │
                                          ▼
                          src/ai/analyst.ts: explainReport()  (UNCHANGED)
                                          │
                                          ▼
                       grounding check (src/ai/grounding.ts, UNCHANGED)
                                          │
                                          ▼
                            shown / rejected / unavailable
```

`src/ai/analyst.ts`, `src/ai/grounding.ts`, and every AI provider are
**unchanged** by this milestone. `explainReport(provider, report)` already
takes any `Report` — the Daily Brief is a second, richer `Report` fed
through the identical pipeline the M10/M11 "Explain this period" feature
uses. This is the M11 architecture doing exactly what it was built for:
"Adding a new provider must not require changing any caller of the AI
layer" (`CLAUDE.md` §12) generalizes here to "feeding a richer payload
must not require changing the AI layer" — and it doesn't.

## Report construction (`src/views/dailyBriefView.ts`)

`getDailyBriefReport(db)` builds eight sections, in this order, each a
direct restatement of an existing `Insight<T>` — no new calculation:

| Section | Source | What it answers |
|---|---|---|
| Position | `getCommandCenterView` (net worth, portfolio valuation, cash, liabilities) | What do I have right now |
| Changes | `behavioralIntelligenceView.whatsChanged` | What changed since last month |
| Why | `wealthIntelligenceView.netWorthWaterfall` | What is driving the change |
| Deviations | `investmentIntelligenceView.plannedVsActualAllocation`, `goalLiabilityIntelligenceView.goalCollisionDetector` | Where has reality deviated from plan |
| Risks | `investmentIntelligenceView.concentrationHeatmap`/`drawdownMonitor`, `behavioralIntelligenceView.anomalyDetector` | What risks exist |
| Goals | `goalLiabilityIntelligenceView.goalFundingRadar` | Am I on track for my goals |
| Portfolio | `investmentIntelligenceView.portfolioXRay`/`performance` | What does my portfolio look like |
| Data quality | `behavioralIntelligenceView.healthScore`/`dataHealth` | Is my data trustworthy; what needs review |

Where a source `Insight` is `insufficient-data`, the section states that
plainly (`fact("Insufficient data — <reasons>")`) rather than omitting the
section or inventing a number.

## FACT / INFERENCE / RECOMMENDATION

Every line uses the same three-way `ReportLine` distinction M10 already
established (`src/views/reportView.ts`), reused as-is:

- **FACT** — a direct restatement of a computed figure (a balance, a
  holding's value, a goal's progress). Always attributable to one
  `Insight<T>` field.
- **INFERENCE** — a pattern the rule-based layer identifies across facts
  (a concentration above the existing 25% threshold, a plan-vs-actual
  drift, an anomaly finding, an unexplained gap in a decomposition). Never
  a new heuristic invented for this milestone — every inference here reads
  a severity or a status field an existing `Insight` already computed
  (`concentratedThresholdRatio`, `status: "overweight"`, an anomaly
  finding, `!decomposition.isComplete`).
- **RECOMMENDATION** — a suggestion, always phrased as one, never an
  instruction. The rule-based layer emits at most a handful (reviewing a
  goal-collision shortfall, reviewing needs-review/rejected records) — the
  AI is instructed by the same `SYSTEM_PROMPT` every other AI Analyst
  request uses to add its own RECOMMENDATION section on top, but that
  narrative recommendation is generated by the model, never treated as
  something the system can act on automatically (`CLAUDE.md` §12, "No
  AI-initiated writes to financial data, ever").

The AI never independently calculates a figure: `explainReport`'s
`SYSTEM_PROMPT` (unchanged) instructs "Use ONLY the figures given to you
below," and `checkGrounding` (unchanged) rejects the response outright —
never shown, not even with a caveat — if it states a number not present in
the report text.

## UI

Surfaced on the existing AI Analyst screen (`src/app/ai-analyst/page.tsx`)
as a second action, "Generate daily brief," alongside "Explain this
period." Both write their outcome as an `audit_event` and redirect the
screen to it, sharing one helper (`runGroundedExplanation` in
`src/app/ai-analyst/actions.ts`) that differs only in which `Report` it
builds and which audit-log/query-param name it uses (`ai_explanation`/
`event` vs `ai_daily_brief`/`brief`). An unavailable or rejected outcome
is shown exactly as plainly as a shown one, per
`docs/18_FAILURE_MODES.md`.

IM-08 (Command Center 2.0) is expected to move the Daily Brief to the top
of the redesigned Command Center per the v1.1 directive's specified
section order — this milestone deliberately does not move it there yet,
to keep IM-07 scoped to the brief's own construction and grounding rather
than the dashboard redesign.

## Testing

- `tests/views/dailyBriefView.test.ts`: an empty-database case (all eight
  sections present, every section has at least one honest line, no
  crash) and a real-fixture case (restates a real net worth figure, a
  real holding name, a real goal name, and emits a RECOMMENDATION line for
  a needs-review record — plus a grounding-payload check confirming the
  same text `explainReport` would receive contains the real figures and
  the `[FACT]`/etc. labels `buildGroundingPayload` emits).
- `tests/e2e/dashboard.spec.ts`: "generates a Daily Brief through the same
  grounding pipeline" — clicks the new button, confirms it reaches the
  same AI-unavailable outcome the existing "Explain this period" test
  already exercises (this sandbox has no reachable Ollama), on both
  laptop and iPad viewports.
